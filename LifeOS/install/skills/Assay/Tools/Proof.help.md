# Proof.ts — output checks

Is this artifact what the brief asked for? Proof compiles briefs into typed checks, checks the plan against them, then runs them on the artifact. Code decides what it can; the judgment layer (caller `proof`, question `intent`, shadow) adds flags that never block. Every run writes a receipt through `LIFEOS/TOOLS/lib/ProofReceipt.ts`.

## Commands

Flags, one line each:

- `plan --brief <file>` (repeatable) compiles briefs into checks; `--plan <file>` adds plan-drift against a storyboard, outline or spec; `--kind` is required; `--out <proof.json>` writes the checks file (required with `--brief`); `--json` prints the checks file.
- `plan --ask <file|->` compiles from the ask text (`-` is stdin) and fills the compile cache; `--out` is optional here.
- `run --artifact <file>` is required. `--checks <proof.json>` or `--ask <file|->` supplies compiled checks (not both). With neither, and no ISA, the receipt says so: `ideal_state` is `{kind: "none"}` and no compile ran.
- `run --skill <Name>` loads that skill's StandingChecks.json; `--session <id>` names the session whose latest run attributes the skill and whose active ISA is the ideal state (default `CLAUDE_SESSION_ID`).
- `run --isa <ISA.md>` measures against that ISA revision; `--criteria ISC-1,ISC-2` narrows it (needs `--isa`; it does not apply to `--intent`).
- `run --intent <skills/<S>/Intents/<I>.md>` (or a single-intent skill's `SKILL.md`) adds that intent's Ideal State and Anti-criteria bullets as checks and names the intent as the ideal state. With an explicit `--skill <Name>` and none of `--isa`, `--intent`, `--ask`, `--checks`, the intent of that skill this session last read is used (§ Intent as the ideal state below).
- `plan --intent <file> --kind <kind>` prints the checks an intent compiles to, with no model; `--out` writes them, `--json` prints them.
- `run --destination handoff|send|publish|deploy|isa-close|none` sets where the output is going; it changes the safety severity (default `handoff`).
- `run --escalate` is opt-in: after the judgment-layer batch, every judgment-layer check that stayed unsure goes to the Assay judge in ONE batched call (see Escalation below). Off by default; a gate never sets it.
- `run --project <dir>` is the HyperFrames composition for frame, mark and OCR checks; `--at t1,t2` and `--hits <hits.md>` pick the sampled times; `--json` prints the receipt.
- `receipt --artifact <file>` asks whether a fresh receipt admits the bytes (exit 0 only then).
- `reference --artifact <file> --reason "<why>"` records reference material that is not a produced output.
- `dismiss --artifact <file> --check <id> --reason "<why>" [--by <who>]` records why an unearned flag does not apply (a proxy label).
- `miss --kind <kind> --check '<json>' --note "<what was caught>"` adds a standing check for a kind; `miss --skill <Name> [--kind <kind>]` adds it to that skill's StandingChecks.json.
- `retire --skill <Name> | --kind <kind> --check <id> --reason "<why>"` retires a standing check that keeps missing (ISC-37): it stays in its file marked `retired` as the record and stops compiling into runs. `Errata.ts misses` lists candidates with the command.

```
bun skills/Assay/Tools/Proof.ts plan --brief <file> [--brief <file>...] [--plan <file>] --kind <video|image|audio|text|page|doc> --out <proof.json> [--json]
bun skills/Assay/Tools/Proof.ts plan --ask <file|-> --kind <kind> [--out <proof.json>] [--json]
bun skills/Assay/Tools/Proof.ts plan --intent <intent.md> --kind <kind> [--out <file>] [--json]
bun skills/Assay/Tools/Proof.ts run --artifact <file> [--checks <proof.json> | --ask <file|->] [--skill <Name>] [--session <id>] [--project <hyperframes dir>] [--at t1,t2,...|--hits <hits.md>] [--isa <ISA.md> [--criteria ISC-1,ISC-2]] [--destination handoff|send|publish|deploy|isa-close|none] [--escalate] [--json]
bun skills/Assay/Tools/Proof.ts run --artifact <file> --intent <intent.md> [--checks <proof.json> | --ask <file|->] [any other run flag above]
bun skills/Assay/Tools/Proof.ts receipt --artifact <file>
bun skills/Assay/Tools/Proof.ts reference --artifact <file> --reason "<why this is not a produced output>"
bun skills/Assay/Tools/Proof.ts dismiss --artifact <file> --check <id> --reason "<why the flag does not apply>" [--by <who>]
bun skills/Assay/Tools/Proof.ts miss --kind <kind> --check '<json>' --note "<what the principal caught>"
bun skills/Assay/Tools/Proof.ts miss --skill <Name> [--kind <kind>] --check '<json>' --note "<what the principal caught>"
```

## Text-bearing outputs, the ask, and safety (S5)

Plain text and markdown, an HTML page, a PDF and a Word, Pages, RTF or ODT document all get a real proof in about a second. The artifact is reduced to text, then one set of text checks runs on it.

- **Kinds.** `text` (.txt .md .markdown .json .csv) is read as it is. `page` (.html .htm) becomes its visible text in code, with no browser: comments, script, style and head are dropped, an element that hides itself by attribute (a bare `hidden`, `aria-hidden="true"`, an inline `display:none` or `visibility:hidden`) is dropped when no element of the same name is nested in it, image alt text is kept, headings become `#` lines, list items `- ` lines and links `[text](href)`, and entities are decoded. `doc` is a PDF through `pdftotext -layout`, or docx, doc, rtf and odt through `textutil -convert txt`. A `.pages` file is not a doc: textutil cannot read it, so it is unproofed like `.pptx`. Hiding by class (`.sr-only`, a stylesheet rule) cannot be seen from the source: only the frame path (`--project`) catches it. A page proofed with `--project` keeps the frame and OCR path; a bare page goes the text path. `PROOF_PDFTOTEXT`, `PROOF_PDFINFO` and `PROOF_TEXTUTIL` override the binaries.
- **PDF honesty.** Pages are split on the form feed before any cleanup. When N of M pages (M from `pdfinfo`, else the separator count) have no text layer, the run measures the rest and records `unavailable` `extract`, "N of M pages have no text layer", so the verdict is never a clean pass. A PDF is read twice, with and without `-layout`: a literal found in either reading satisfies `text-present`, and one found in either reading violates `text-absent`; counts and judgment-layer questions read the layout reading.
- **Extraction failure is unavailable, never a pass.** A missing binary, an encrypted or corrupt PDF, a non-empty file that yields no text (a scan with no text layer, a page that renders only from script) records an `unavailable` `extract` finding and an `unavailable` `safety-scan` finding; the run exits 2.
- **Compile from the ask.** `run --ask <file|->` (`-` is stdin) compiles checks from the ask text with one model call, then runs, in one command. The call uses the cheapest lane that holds quality: `inference()` at `low` on the Anthropic lane by default, never Haiku; `LIFEOS_PROOF_COMPILE_VENDOR` may name another approved evaluator vendor (see Egress below), and anything outside that set makes no call. It is cached by the sha256 of `{COMPILE_VERSION, kind, ask}`. `plan --ask` fills the same cache, so a later `run --ask` makes no model call; `--out` also writes the checks file. The receipt's `ideal_state` is `{kind: "ask", sha256}` and `profile` carries `ask:<sha12>`. `--ask` and `--checks` together are a usage error. If the compile cannot run, the run still goes: `extractCountables` + safety + profile + standing checks, plus an `unavailable` `compile` finding, so the verdict can be a fail but never a clean pass.
- **Countable requirements are code (C14).** `word-count` {min?, max?}, `length-chars` {min?, max?} (spaces included) and `count` {pattern, regex?, min?, max?} (occurrences of a phrase, or of bullets, headings, links, sentences, paragraphs by regex; run with the g, i, m flags) are measured over the extracted text, bounds inclusive. The compile prompt routes anything countable to them and never to the judgment layer. `verifyChecks` rewrites a judgment-layer question that is really a count ("fewer than 80 words") into the code type, quoting the brief, or drops it with a reason when its unit has no counter ("at most five items"). `extractCountables(brief)` is the deterministic pre-compiler: it pulls "fewer than N", "at most N", "under N", "more than N", "at least N", "exactly N" and "between N and M" over words, characters, bullets, links, headings, sentences and paragraphs by regex, with no model; "N words per slide" is not a whole-output count and is skipped. Number words (one to twenty, thirty, forty, fifty, hundred) count. Negations read as written: "not less than / not under / not fewer than / never fewer than N" is a minimum of N; "not over / not above / not more than / never more than / not longer than N" is a maximum of N; a plain "under N" inside a negation is not read twice. "N words or fewer", "or less", "max", "maximum", "tops" and "max. N words" are a maximum of N. A soft target ("a 200-word summary", "about / around / roughly / approximately / ~ N words", also characters) is a band of plus or minus 10 percent, rounded: 200 is 180 to 220. A number or range before a singular unit that describes each part ("a 2-3 word title", "a 1-2 sentence hook", "a 10-word headline") is per item and emits no whole-output check; "N-word" is a whole-output target only before a noun that names the whole output (summary, blurb, post, essay, response and the like), and never when each/per/every follows. On a page, `length-chars` counts the prose view, with link targets stripped. A judgment-layer question that is a count with no code counter is dropped, and the receipt's `profile` carries `dropped-countable:<id>`.
- **Safety is code, always on, never compiled (ISC-36).** Every run on a kind with a body adds, in `runProof` after compile, `safety-secret` (the secret value shapes in `hooks/lib/egress-shapes.ts`, the one list the harness uses, plus its KEY=value shape), `safety-private-key` and `safety-home-path`. They read nothing the brief, plan, checks file or artifact says about them. Ids starting `safety-` in any case (`Safety-x` too) are reserved: a compiled, standing, skill or checks-file check that uses one is dropped and named in `profile` as `dropped-reserved-id:<id>`. The compile prompt and the judgment-layer judge wrap the brief as trusted requirements and the artifact as an `<<<ARTIFACT_EVIDENCE>>>` block of untrusted data whose text is never an instruction.
  - **Where it runs.** text, a bare page and a doc: the extracted text, the raw source, and a PDF's second reading. A page with `--project`: its `index.html` source and the page file, and the OCR'd frame text. Video and image: the OCR'd text of the sampled frames (OCR can misread a character, so a secret in a picture is caught only when it is read exactly). Audio has no body. If the scan cannot run (no frame text, an unreadable `IdentityTerms.json`), it records an `unavailable` `safety-scan` finding, never a pass.
  - **Severity depends on what was found and where the output is going** (the receipt's `destination`, default `handoff`). A **real secret**, meaning a shape match whose value has at least 3.0 bits of Shannon entropy per character and is not placeholder-shaped, **fails at every destination**. A **placeholder-shaped secret** flags (`placeholder-shaped secret`) and never fails: a value containing `xxxx`, `YOUR_`, `EXAMPLE`, `<...>` or `...`, a value with fewer than 4 distinct characters, a value below the entropy floor, the public jwt.io sample token, and `AKIA...EXAMPLE`. A KEY=value or a bearer token must also look random (a digit, or mixed case) and not be a code reference such as `process.env.X`, or it is a flag too. A **private-key PEM block** (header in any case plus a key body) fails everywhere; a header with no body flags. **The real user's own path** is the literal home directory, `/Users/<user>` and `/home/<user>` (no trailing slash needed) and the names in the optional USER file `LIFEOS/USER/CUSTOMIZATIONS/SKILLS/Assay/IdentityTerms.json` (`{"terms":["name"]}`, read at run time, absent means none, each term read as a user name in those path forms): it **fails when the destination is send, publish or deploy** and **flags on handoff, isa-close and none**. Any other `/Users/<other>/`, `/home/<other>/`, `C:\Users\<x>\` and `/root/` only flag. `~/.claude` and `$HOME/.config/LIFEOS` (`${HOME}/…` too) are the documented install paths and are never a finding.
  - **Views.** Every hit in any view counts: the raw source; the source with entities decoded (tags kept, so a secret in a comment, an attribute or a script is read); the visible text; a normalized form of each (soft hyphens and format characters stripped, numeric and named invisible entities decoded, `%XX` decoded, NFKC); decoded `data:...;base64,` URIs and standalone base64 runs of 24 or more characters that decode to printable text; and a whitespace-collapsed form (all whitespace and the `" + "` concatenation pattern removed) read for the fixed-prefix shapes only, and only where the prefix began a word in the source. `Bearer` and the PEM header are case-insensitive. JS string escapes (`\x73k-…`) and arbitrary obfuscation are out of reach, as for any secret scanner. Values are masked in findings.
- **Per-skill standing checks.** `--skill <Name>` loads `LIFEOS/USER/CUSTOMIZATIONS/SKILLS/<Name>/StandingChecks.json` (the `standing-<kind>.json` schema, validated; `LIFEOS_PROOF_SKILL_STANDING` overrides the root) in addition to the kind's standing checks. A check that does not validate is named in `profile` as `skill-standing-dropped:…`. `miss --skill` appends to that file atomically. With no `--skill`, `run` infers the skill from `--session` (else `CLAUDE_SESSION_ID`) through `hooks/lib/run-attribution.ts`, only when that skill has a StandingChecks.json; otherwise it stays explicit.
- **No money allowlist on text.** A price in an ask is not a requirement that the output display it, and the allowlist and legibility checks read a rendered frame, so text, page-as-text and doc runs skip them. Say it in the ask ("must mention $480") and it compiles to `text-present`.

- `plan` makes one Anthropic-lane `inference()` call, cached by the sha256 of its inputs. It drops any check whose `derived_from` is not a whitespace- and case-normalised substring of the brief. When `--plan` is given, it adds a `plan-drift` finding for every required literal the plan never carries, and exits 1.
- `run` samples frames (ISC-26). With hits (`--hits`, else the project's own `hits.md`): every hit time, each beat's end (next hit minus 0.15 s), the middle of every gap of 1 s or more (0 → hits → end), and the true last frame. With no hits and no `--at`: 12 uniform samples plus the last frame. `--at` and each check's own `at` (+0.5 s) add on top. Times within 0.25 s merge, and a rest frame (beat end, gap middle, last frame) wins its cluster. A video whose sampled times miss the last 0.5 s or leave a gap over 10 s gets an `unavailable` `coverage` finding (ISC-30). The kind comes from the artifact's extension (a project with no known extension means video), never from a flag or the checks file; a mismatch is recorded in `profile` as `checks-kind:<a>≠<b>`. Receipts carry `brief_sha256`, `checks_sha256` and `sampled_times`. With `--project`, frames come from the HyperFrames composition opened headless: overlay marks (`data-annotates`, `data-mark`, stroked `data-textfit="cover-ok"`) are read from the DOM, one screenshot is taken with the marks hidden (for OCR) and one as rendered (for crops). The clean frame hides marks only: never an element over 25% of the frame and never one with a CSS `filter` or `backdrop-filter`, so OCR cannot read text the viewer never sees, such as a blurred byline. An image proofed with `--project` is composed at every `--at` time (a seam still-proof passes all of them); with no `--at`, at 0.
- A video run with `--project` certifies the film, not only the composition. The receipt records `composition_sha256` (the sha256 of index.html). Proof extracts the film at up to 3 composed times (frames with no mark on screen first, then the most words), OCRs them, and requires 80% of the composed frame's confident words of 12 px (per 1080 px) or more to be read in the film at the same time; a lower match is an `unavailable` `composition` finding, "film does not match its composition". A film older than the newest `*.html` in the project is only a hint: when its frames match, the run records `composition-match:…(film older than its HTML; frames match, so not stale)` in `profile` and does not block; when they cannot be compared, it is `unavailable`, "artifact predates its composition; re-render".
- **Film text (ISC-14).** With `--project`, `text-present`, `text-absent` and `prominent` read the composition's own DOM words at each sampled time (visible, at least 15% opaque, at least half inside the frame and every overflow or `inset()` clip; one line key per block element, so wrapped phrases match); OCR is the fallback when a frame has no DOM, and a present-check the DOM misses retries OCR on that frame. A `text-present` or `prominent` check aimed at row times passes when any sample inside its row shows it: a row runs from its `at` time to the next row start any check names (or its own `until`), the last row to the end. A check whose `required` is `false`, or whose quote calls the fact optional ("optional", "may appear", "if shown"), is a flag when missing, never a fail; `text-absent` and the money allowlist still fail a wrong value.
- Otherwise a check aimed at named times (`at: [t…]`) takes the nearest sampled frame within 1 s of `t + 0.5`. A check whose times resolve to no frame, glance included, is never passed: on a video it is `unavailable`; on a still set (an image with `--project`), which is partial by design, it is recorded as `<id>:n/a(no still at <t> s)` in `profile`.
- `receipt` exits 0 when a fresh receipt has no code fail and no earned fail (or is a reference). Open unearned flags do not block: they are named in the output and recorded on the receipt (principal, 2026-09-30). An unavailable check never reads as a pass.
- `dismiss` appends a `ProofDismissal` (check, reason, at, by) to the fresh receipt (ISC-31). It refuses a missing or stale receipt and a check id that names no flag in the receipt (exit 1), and a reason under 8 characters (exit 64).
- `miss` appends a standing check to `LIFEOS/USER/CUSTOMIZATIONS/SKILLS/Assay/Proof/standing-<kind>.json`; it applies on the next run of that kind.
- There is no census and no `outputs:` frontmatter: a skill declares nothing to be covered. Hooks and send tools record outputs; coverage is measured against events the gates do not control (`LIFEOS/DOCUMENTATION/Assay/AssaySystem.md` § Coverage).

## Intent as the ideal state: `run --intent` (intent-ideal-state ISC-9)

Every skill intent opens with `## Ideal State` and `## Anti-criteria` (`LIFEOS/DOCUMENTATION/Skills/SkillSystem.md` § Intent anatomy). `--intent` makes those bullets the checks, so the definition of done the model read is the one its output is held to.

- **Compile, no model.** The intent is read through `LIFEOS/TOOLS/lib/IntentSections.ts`. Each Ideal State bullet becomes check `intent-is-<n>` and each Anti-criteria bullet `intent-ac-<n>`; `derived_from` is the bullet, verbatim. A bullet a program can count ("under 60 words", "more than 3 bullets") is the same code check the ask compiler makes (`countablesIn`, plus the media countables for image and video). Everything else is one judgment-layer question per bullet, asked in the run's one batch: "Does the output meet this Ideal State criterion of the <Skill> <Intent> intent: …?". No cache and no compile outage: the same bytes give the same checks.
- **Anti-criteria are must-nots.** The check carries `polarity: "must-not"`. Its judgment-layer question asks whether the output is free of what the bullet forbids (yes = met). A countable one is the inverted bound: "more than 3 bullets" holds the output to max 3, "fewer than 50 words" to min 50. A range, an exact or soft target, or a duration cannot be one inverted check and is dropped with that reason.
- **Dropped is recorded.** A bullet whose check does not apply to the artifact's kind (every bullet on audio), or a countable one with no counter, is named in `profile` as `intent-dropped:<id>`.
- **Receipt.** `ideal_state` is `{kind: "isa", path: <intent>, revision: <sha256 of the intent bytes>, criteria: [IS-1…, AC-1…], source: "intent", skill, intent}`. The receipt schema (`LIFEOS/TOOLS/lib/ProofReceipt.ts`) admits `isa|ask|none` today and an intent is a small ISA, so it rides that shape and `source` says which it is. `profile` carries `intent:<Skill>/<Intent>@<sha12>` and `intent-source:explicit|auto`.
- **Precedence.** An explicit `--isa` names the ideal state (the intent's checks still run). Otherwise the intent does, ahead of the session's active ISA, the ask and none. `--intent` composes with `--ask` or `--checks` (still one of those two): the ask's checks are this run's specifics, the intent's are what every output of that intent must be, and all of them run. A compiled check whose id collides with an intent check is renamed `<id>-x`.
- **No Ideal State: fall back, said out loud.** An intent with no Ideal State bullets yields no checks; `profile` carries `intent-fallback:no-ideal-state`, the CLI prints why on stderr, and when nothing else names the ideal state its `none` reason says the intent had none.
- **Auto-resolution.** With an explicit `--skill <Name>` and none of `--isa`, `--intent`, `--ask`, `--checks`, Proof reads the tail of `MEMORY/OBSERVABILITY/tool-activity.jsonl` (EventLogger writes one line per tool call: `session_id`, `tool_name`, a JSON `tool_input_preview`) back up to 64 MB or 12 hours, and takes the newest `Read` of `skills/<Name>/Intents/*.md` in this session (`--session`, else `CLAUDE_SESSION_ID`, else `CLAUDE_CODE_SESSION_ID`) whose file still exists. A Read inside a subagent carries the session id and counts; a `cat` through Bash does not. Nothing found: the run is exactly what it was. `LIFEOS_PROOF_TOOL_ACTIVITY` points the lookup at another log (tests). A skill inferred from the session (no `--skill`) never triggers it, and the library entry `runProof` never resolves on its own, so gates are unaffected.

## Image and video: compile from the ask (S7)

`run --ask` and `plan --ask` compile an image or a video the same way they compile text: one cached model call (the cache key is the sha256 of {COMPILE_VERSION, kind, ask}), with the deterministic pre-compile first so the countable checks exist when the compile cannot run. A diff or patch (`.diff`, `.patch`, or `--kind diff`) is proofed as text: the text checks and the safety scan read it as it is.

- **Countables are code.** For an image or video the ask's counts become code checks measured on what Proof already reads: `word-count`, `length-chars` and `count` over the OCR text of the frame (an image's one frame; a film's sampled frame with the most words, never a sum across frames that repeat text), `dimensions` {width, height} ("1080x1920", "1920 by 1080": exact pixels, read by magick or ffprobe), `duration` {min, max} in seconds ("under 30 seconds" is max 29.99; minutes convert; ffprobe) and `frame-count` {min, max} ("exactly 600 frames"; the container's own frame count, unavailable when it does not state one). `duration` and `frame-count` are video only. A measurement that cannot run is unavailable, never a pass.
- **Judgment is the judgment layer.** What no count decides becomes a `glance` check over the OCR token and mark state Proof already builds per frame (`frameState`), asked in the one pooled batch.
- **Egress.** The compile's call passes `assertEvaluatorVendor` before the cache and before any call; the ask is treated as private. A vendor outside anthropic, openai, google and cloudflare (`LIFEOS_PROOF_COMPILE_VENDOR`, default anthropic) makes no call: the file carries `compile_unavailable: "egress refused: ..."` and the run records an unavailable `compile` finding beside the deterministic checks.

## The default layout class (ISC-13)

Every video, image and page run carries layout checks whether or not the brief mentions layout. They are built-in profile checks with reserved ids (`layout-default-` prefix, like `safety-`): a compiled, standing, skill or checks-file check with such an id is dropped and named `dropped-reserved-id:<id>`, and a compiled check of type `layout-fit` or `layout-judge` is dropped too. A brief can add checks; it can never turn these off.

- **`layout-default-fit` (code).** With `--project` (a video or a page), `skills/HyperFrames/Tools/TextFit.ts --project <dir> --every 0.5 --json` runs on the composition, beside frame capture (`--times 0` for a page or a film with no duration). Each TextFit row whose kinds include occluded, canvas-text, connector, align, clipped or frame is one code fail with its time, selector and detail; covered, truncated and optout stay TextFit's own gate. TextFit exiting 2 or 3, or printing no findings array, is `unavailable`. With no `--project` it is `layout-default-fit:n/a(no --project; …)`. The profile entry becomes `layout-default-fit:textfit <rows> row(s), <n> in fail kinds`.
- **`layout-default-judge` (judged).** The four questions of `Suites/Capability/visual-layout.yaml` (its first case's `vision-rubric` asserts, threshold 0.75) are asked of up to 12 sampled frames, evenly spread, through VisionJudge's OpenAI + Anthropic panel; never Google. Every layout finding carries the suite's calibration, read at run time from `<configRoot>/LIFEOS/USER/CUSTOMIZATIONS/SKILLS/Assay/Calibration/visual-layout.result.json` (agreement, defects caught, false alarms; a missing record says so). Once that record is earned, a question both vendors fail is a blocking `fail` (`tier: judge`, `earned: true`, the Critique `--layout-qa` rule); while it is provisional that is a `flag`. A question one vendor fails is a `flag`, and a missing seat is `unavailable`, never a pass. Findings are `layout-default-judge:q1`…`q4` with a whole-frame crop. The profile entry becomes `layout-default-judge:frames <n>/<sampled>, questions 4, panel openai+anthropic, <s>s`.
- **Where no judge runs.** After a safety fail the judge is withheld (`withheld(safety)`). A caller that passes its own `judgeManyFn` and no `layoutJudgeFn` (a send gate: "no judge runs inside a gate") gets `layout-default-judge:not-run(…)`; `layoutJudgeFn: null` withholds it explicitly. A caller that supplies its own `composeFn` without a `textFitFn` gets `layout-default-fit:not-run(…)`, because TextFit opens the real composition. None of these is counted as a pass.

## Escalation: `run --escalate` (S7)

Cheapest first: code for what a program can count, then one judgment-layer batch for the judgment checks, then a judge only on escalation. Escalation is opt-in and off the blocking path.

- **What escalates.** Each judgment-layer check that came back unsure (decide() said not confident either way: the finding carries `unsure: true`). Proof reads no threshold and no probability band; the unsure mark the receipt already records is the only trigger. All of them go to the Assay judge in one batched call, after the judgment-layer batch. The judge is the strict assertion checker of Judge.ts's llm-assert on the Assay judge lane (`evalJudgeVendor()`, level high), after `assertEvaluatorVendor`.
- **What the judge's answer does.** It is recorded on the finding as tier `judge`. `yes` clears the unsure flag (a pass). `no` is a `flag`, never blocking, unless the judge is earned (`LabelStore.earnedStatus` for caller `proof-judge`, question `intent`, principal labels only); then it is an earned `fail`. `unknown` leaves the judgment layer's unsure flag and adds a judge flag saying it could not tell.
- **Never after a safety fail.** If a `safety-*` check failed, or the safety scan could not run, the judge is not called (the same rule as the judgment layer withholding) and the profile records `escalate:withheld(safety)`. With nothing unsure it records `escalate:none-unsure`; after a call, `escalate:judge(<n>)`.
- **An unavailable judge is unavailable.** A judge that throws, is refused at the egress check, or omits a check leaves the judgment layer's unsure flag in place and adds an `unavailable` judge finding for each: the verdict reads unavailable (exit 2), never a pass.
- **Receipt.** `evaluators.judge` names the judge model that answered.
- **Gates never escalate.** SendGate (`LIFEOS/TOOLS/lib/SendGate.ts`, shipped) calls `runProof` without `escalate`. The ProofGate and ReplyRecord hooks (maintainer-side; not in the public release) do the same or read receipts only; ProofGate reads stored receipts through `mayPresent` and runs nothing.

## Sends

Send tools call SendGate (`LIFEOS/TOOLS/lib/SendGate.ts`) before the network call; Slack MCP sends go through the MCP send-gate hook (maintainer-side, not shipped). Full contract: `LIFEOS/DOCUMENTATION/Assay/AssaySystem.md` § Sends and publishes.

- The gate always runs the code tier on the exact bytes at the send's own destination (`send` or `publish`); `bun skills/Assay/Tools/Proof.ts run --artifact <file> --destination send` is the same check. A stored receipt never admits a send; it can only add an earned no from a judge that really ran.
- No judge runs in a gate, so a model check reads unavailable there. A code fail, an earned no or an unavailable measurement blocks; unearned flags are allowed and printed.
- A message whose every recipient is the principal's own address or line (the tool sets `toPrincipal`) is proofed as a hand-off, not a send. A real secret still fails.
- A block prints the exact bytes' location and the proof command. Only the principal's prompt ("send it anyway", "override", or a bare "y" when the block is newer than the last assistant message) mints a one-use, 15-minute token. The agent cannot touch the state dir, and headless runs get no override.
- Fail closed: a gate error is a block, never a pass.

## Exit codes

| code | meaning |
|---|---|
| 0 | pass (flags allowed) |
| 1 | at least one code-tier failure; `plan` found drift; `receipt` found none, stale, or failing |
| 2 | a check could not be measured (missing tesseract/ffmpeg/magick, a composition that will not open, an unreadable frame, compile inference down) |
| 64 | usage |

## Check types

| type | fields | tier | fails when |
|---|---|---|---|
| `text-present` | `pattern`, `regex?`, `scope?: "prominent"`, `at?` | code | the literal is not on screen (in any sampled frame for `at: "all"`, in each named frame otherwise); with `scope`, it is only smaller than the median text, or, for a money literal, smaller than the display floor |
| `text-present` `money-present-<amount>[-<period>]` | added automatically, one per brief amount: `pattern` = the brief literal, `scope: "prominent"`, `at: "end"` | code | the amount the brief names is not on the final frame at display size; matches every spelling ($480/yr ≈ $480/year ≈ $480 per year ≈ $480) |
| `text-absent` | `pattern`, `regex?`, `at?` | code | the literal appears in any applicable frame |
| `prominent` | `pattern`, `over` (regex), `caption_band?: [y0,y1]` (fractions), `at?` | code | among OCR tokens matching `over`, the `pattern` token is absent or not the tallest (ties: nearest the centre) |
| `mark-crosses-text` | — (standing) | code | any overlay mark's stroke band crosses an OCR word read at confidence 60 or more; a crossing only a weaker read decides is `unavailable` for that mark |
| `mark-encloses` | — (standing) | code | a mark does not enclose its target with 2 px padding, or its centre is more than 20% of its size off the target's centre on either axis (`mark-misses-target`). The target is `data-annotates-text` found by OCR (confidence 60 or more, crop fallback included) on the marks-hidden frame, or the DOM box of a `data-annotates` selector. With no declared mark that names a target, it is recorded as `mark-encloses:n/a(no declared marks)` and never counted as passed |
| `mark-strikes` | — (standing) | code | a `data-mark="strike"` bar, measured in the page after fonts load, sits more than 15% of cap height off its word's cap middle (baseline minus half the cap height, from the Range rect and canvas TextMetrics), or does not cover the word, or overhangs it by more than 12 px on a side. The word is `data-annotates="<id>"` or the text beside the bar in its own parent; a strike with neither fails. A bar still drawing in (painted narrower than its layout box) is judged on height only at that time. A strike is exempt from `mark-encloses`, and `mark-crosses-text` ignores its own word only. With no strike on any sampled frame it is recorded `mark-strikes:n/a(no strike marks)` |
| `mark-undeclared` | — (standing) | code | an undeclared ring (bordered on every side, text-empty, over a plate, at most 3% of the frame, not a panel, not framing its container) sits next to a word read at confidence 60 or more while enclosing none: a ring beside its number, which nothing else catches. Also an undeclared overlay: a text-empty, filled or bordered element wider than tall and under 40% of the crossed text's font size tall, with no `data-mark` on it or an ancestor, whose box crosses the DOM-measured ink of visible text it does not contain. A `cover-ok` reason does not declare it. It is reported here once, never also as `mark-crosses-text` |
| `nondegenerate` | — (standing) | code | the frame's luma standard deviation is under 0.01 |
| `non-empty` | — (standing, text, doc, bare page) | code | the extracted text is empty |
| `word-count` | `min?`, `max?` (inclusive) | code | the words in the extracted text (whitespace tokens with a letter or digit, markdown link targets excluded) are outside the bounds |
| `length-chars` | `min?`, `max?` (inclusive) | code | the trimmed text's characters (spaces included) are outside the bounds |
| `count` | `pattern`, `regex?`, `min?`, `max?` | code | occurrences of the phrase (case-insensitive) or the regex (g, i, m) are outside the bounds |
| `duration` | `min?`, `max?` seconds (video) | code | ffprobe duration is outside the bounds |
| `frame-count` | `min?`, `max?` (video) | code | the container frame count is outside the bounds; unavailable when it states none |
| `dimensions` | `width?`, `height?` (image, video) | code | the pixel size is not exactly the named width and height |
| `safety-secret`, `safety-private-key`, `safety-home-path` | — added by code on every run with a body; not a check any file can declare | code | a real secret or a private-key block is in the output (any destination), or the real user's own path is in an output going to send, publish or deploy. A placeholder-shaped secret, a bare PEM header, another user's path and the real user's path on a hand-off are flags |
| `gatescan` | — (standing, audio) | code | `skills/AudioEditor/Tools/GateScan.ts --json` finds audible gate steps |
| `loudness` | `target_lufs?` (−14), `tolerance?` (1) | code | ffmpeg ebur128 integrated loudness is outside the target |
| `money-allowlist` | `allowed` (amounts) — added automatically whenever the brief names money | code | among display-sized money tokens (glyph height ≥ max(30 px per 1080 px, min(1.5× the median token height, 0.5× the tallest token))), the most prominent is not one the brief names; body-copy amounts never count |
| `legibility` | `allowed` — added automatically with the allowlist | code | at the true last frame, and at any frame with a display-sized money token, a named amount is under 24 px tall per 1080 px of frame height (ISC-35) |
| `glance` | `question` | glance | never fails: one aggregated `flag` per check (frames flagged / asked, worst p, worst frame's crop) when p(no) ≥ the caller threshold (provisional 0.85); `at: "all"` samples at most 8 frames |

Money literals are a class `{amount, period}`: `$480/yr`, `$480/year`, `$480 / year`, `$480 per year` match each other and a bare `$480` (ISC-28). Tokens under tesseract confidence 60 never decide `text-absent`, `money-allowlist`, `prominent` or `text-present`: a frame where the deciding or required token reads only below 60 is `unavailable` for that check, never a pass. Marks: overlays covering more than 25% of the frame are panels or glows, skipped and recorded as `mark <selector>:n/a(panel)` in `profile`; a bordered, text-empty element painted over a raster plate counts as a mark with no declaration (ISC-27). Compose runs up to 4 headless browsers in parallel (`PROOF_COMPOSE_WORKERS`) and takes the second, marks-visible screenshot only when a mark is on screen.

Plan-check also flags a plan line naming a pricing surface (`/pric(e|ing)|offer|CTA|plan card|checkout/i`) that carries no amount while the brief names one (ISC-29). It also runs with no model: every money amount, percentage (not behind ≥/≤), URL or domain, and count literal (`3,000+`, `14-day`, `1–100`; durations and fps skipped) in the brief must appear in the plan, normalised (`14-day` ≈ `14 days`, `–` ≈ `to`, `/yr` ≈ `/year`, money compared by amount). `--at` and `--hits` combine; times closer than 0.25 s merge. Code findings at adjacent times dedupe into one finding with a time range. Stage timings print on stderr.

Profile notes the compile and the run leave: `compile:0-checks` (an ask of more than 8 words compiled to no check), `dropped-countable:<id>` (a count with no code counter was dropped), `skill:<Name>` (that skill's standing checks were loaded), `dropped-reserved-id:<id>`. A compile reply that is an object without a `checks` array (`{}`, `{"error": …}`) is an outage: the run records an `unavailable` `compile` finding and the reply is never cached.

Standing profiles: video = nondegenerate, mark-crosses-text, mark-encloses, mark-strikes, mark-undeclared, gatescan + loudness when there is an audio stream, plus the default layout class. image and a page with `--project` = nondegenerate, plus the four mark checks and the default layout class (an image gets only its judged half) (recorded as `n/a(no --project)` otherwise). audio = gatescan, loudness. text, doc and a bare page = non-empty, plus the safety checks; video, image and a page with `--project` get the safety checks over their OCR'd frame text (and a page its source). A bare `.html` file is proofed as text (above); a visual check (`prominent`, `nondegenerate`, …) written for it reads `unavailable`, "needs a rendered frame". The kinds the hand-off gate enforces (video, image, audio, text, page, and pdf/docx/doc/rtf/odt as doc) come from `LIFEOS/TOOLS/lib/ProofKinds.ts`, the same table `kindFromPath` reads; slide decks, keynotes, Pages files and spreadsheets stay `UNPROOFED`.

OCR is local tesseract (TSV), on a 2x grayscale upscale, with a second pass that masks the first pass's words, because tesseract drops small text beside very large text. A currency-only token ("$") is kept and merged with the numeric token after it on the same line when the gap is at most 0.5× the sign's height ("$ 2,400" → "$2,400", union box, weaker confidence), before any check runs. Every visual finding carries `t`, `bbox` and a crop PNG with the defect outlined, in `<receipt>.crops/` beside the receipt.

Judgment layer: all `glance` checks in a run go out as ONE `judgeMany` batch. The state per frame is OCR tokens (text, bbox, height, prominence rank, centre distance) plus marks and time; for text, the text itself. A judgment-layer outage (`LIFEOS_GLANCE_DISABLED=1`, `LIFEOS_INFERENCE_DISABLED`, an engine error) is a finding with `tier: "glance"`, `severity: "unavailable"` and a message starting `glance outage:`, so the run reads `unavailable` (exit 2): the intent checks did not run. No probability ever decides a block.

## Environment

`PROOF_TESSERACT`, `PROOF_FFMPEG`, `PROOF_FFPROBE`, `PROOF_MAGICK`, `PROOF_PDFTOTEXT`, `PROOF_TEXTUTIL` override binaries. `LIFEOS_PROOF_RECEIPTS` (receipts), `LIFEOS_PROOF_CACHE` (compile cache) `LIFEOS_PROOF_STANDING` (standing checks) and `LIFEOS_PROOF_SKILL_STANDING` (per-skill standing checks) override stores for tests.

The judge's earned status is keyed to the judge prompt hash and vendor (`intent@<JUDGE_PROMPT_HASH>:<vendor>` under caller `proof-judge`), so a prompt or vendor change starts it unearned again. A judge "yes" that clears an unsure judgment-layer flag is recorded in `profile` as `<check>:judge-yes(unearned)`.
