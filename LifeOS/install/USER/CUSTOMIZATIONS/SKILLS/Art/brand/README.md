# Brand assets

Your logo, wordmark, favicon, social image, and fonts, in one place, so every skill that ships something public pulls the same mark. Nothing here is generated by LifeOS: brand marks are authored SVG, never generated UI or image-model output (`skills/Webdesign/Intents/NativeDesign.md` line 51); rasterize the PNGs from the SVG with whatever converter you already use.

No shipped code reads a fixed filename from this directory. Intents take the asset you point them at:

- `skills/Art/Intents/EmbossedLogoWallpaper.md` (lines 37, 49): `LOGO_FILE`, a flat, high-contrast PNG of the mark alone
- `skills/Art/Intents/LogoWallpaper.md` (lines 37, 49): `LOGO_DIR`, a directory of PNG and SVG logo files
- `skills/Webdesign/References/InputFormats.md` (lines 91, 102): design briefs want logos as SVG, custom font files, and any brand guide

Recommended layout, so those three ask for the same files:

| File | What it is |
|------|------------|
| `logo-mark.svg` | The mark alone, vector source of truth |
| `logo-mark.png` | The mark rasterized, transparent background, at least 1024 px on the long side; this is the `LOGO_FILE` for wallpapers |
| `logo-mark-white.png` | Same mark in white, for dark grounds and share cards |
| `wordmark.svg` | Name lockup (mark plus text) |
| `favicon.svg` | Simplified mark that reads at 16 px; sites also derive `favicon.ico` and `apple-touch-icon.png` from it |
| `og-image.png` | 1200 × 630 social preview image |
| `fonts/` | Licensed webfont files (`.woff2`) a design may load; free fonts can come from Google Fonts instead |
| `BRAND.md` | Optional: house colors, type pairing, clear-space rules, one paragraph on tone |

Set `LOGO_FILE=$HOME/.claude/LIFEOS/USER/CUSTOMIZATIONS/SKILLS/Art/brand/logo-mark.png` and `LOGO_DIR=$HOME/.claude/LIFEOS/USER/CUSTOMIZATIONS/SKILLS/Art/brand` in your shell and the wallpaper intents find everything without further flags.

This directory is inside the USER tree and is release-excluded, so real assets never ship with the system.
